# 路由器配置

`configs/` 维护 OpenWrt / ImmortalWrt + OpenClash 使用的多网段配置。

- `v8.yaml`：当前路由器推荐模板。
- `v7.yaml` 至 `v3.yaml`：历史版本。
- `rulesets/`：路由器网段专用的自维护直连和住宅白名单规则（内置为作者个人示例，使用前请替换为你自己的域名与 IP）。

使用前应复制 `v8.yaml` 为私有的 `v8.local.yaml`，填写机场订阅、控制器密钥及按需使用的住宅代理凭据。该配置依赖 OpenWrt 的接口、DHCP、Wi-Fi 和防火墙设置，不适合直接导入单设备客户端。

普通代理入口统一为 HTTP `7890`、SOCKS5 `7891`、混合代理 `7893`，账号密码认证在 OpenClash 页面启用和管理。模板不包含真实认证凭据；直接运行 Mihomo 时，需要在私有副本中自行设置 `authentication`。启用配置后应核对 OpenClash 实际加载配置的端口与认证，并验证正确账号可连接、错误账号被拒绝。

规则模式下，普通代理入口与透明代理共用主规则：源 IP 属于 31.x 时直连、32.x 时按平台分流、33.x 时使用全局出口、34.x 时使用住宅白名单子链。程序需要按平台代理时，应部署在 32.x，连接路由器该网段的地址；通过 Zashboard 连接详情核对实际源 IP、命中规则、代理链和最终节点所属机场。

当前 `v8.yaml` 包含 62 个策略组、42 个 rule-provider、12 个地区和 5 个机场 provider。历史 `v7.yaml` 中的独立爬虫 HTTP 入口不属于当前 v8 的使用方式。

`configs/*.yaml` 与 `configs/rulesets/*` 已被部署配置和 GitHub Raw URL 引用，属于稳定公共路径。后续不得为了目录整理而移动或改名；单设备配置统一维护在仓库顶层 `client/`。
